Computational report · single consumer GPU

De novo PD‑L1 miniprotein binders on an 8 GB GPU

A staged screening pipeline that reproduces the Anthropic binder‑design methodology under a hard compute budget: a cheap local co‑fold triage narrows 1,050 candidates, then free cloud co‑folders vote to rank the survivors. From 52 RFdiffusion backbones and 4,905 MPNN sequences to a top‑30 shortlist with <45% sequence identity to the reference PD‑L1 designs.

00 · Motivation

Why this shape of pipeline

The method was chosen by the hardware, not the other way around. Every stage exists to spend the scarce resource — GPU memory and wall‑clock — only where it changes a decision.

The constraint

A single RTX 3070 Ti, 8 GB VRAM inside WSL2/Ubuntu. That is enough to run localColabFold (AlphaFold2‑multimer) on a two‑chain complex — but only just, and only at low settings. It is not enough to run large modern co‑folders (AlphaFold3, Boltz, Chai) locally, nor to fold 1,050 complexes at 5 seeds × high recycle counts in any reasonable time.

The response

Make the first pass cheap and local: one localColabFold prediction per design (recycle 1, single seed), scored with the same interface metrics the reference study uses. Then escalate only survivors to higher‑quality co‑folders through free/low‑cost APIs, and let several models vote. Broad‑and‑cheap first, narrow‑and‑accurate last.

The core idea
Anthropic’s published recipe is a multi‑predictor consensus: fold each design with several co‑folders, keep those all the models agree on, rank by a weighted ipSAE + sc_DockQ z‑score. We keep that logic intact but stage it by cost so it fits in 8 GB: a free local model does the coarse triage, paid/borrowed accuracy is reserved for the shortlist.

02 · Is a cheap ColabFold pass a valid filter?

Evidence that a cheap recycle‑1 ColabFold pass can serve as a coarse triage screen

Before trusting a recycle‑1 local fold to throw candidates away, two things had to be established: that the interface metrics are computed identically to the reference method, and that a single cheap recycle‑1 prediction still tracks the expensive multi‑model consensus.

Same metrics, same code path

Both screening metrics are computed exactly as in the dataset methodology, from the localColabFold complex prediction (chain A = PD‑L1 target, chain B = designed binder):

  • ipSAEmin — the interface‑pyramid score of Dunbrack’s ipsae.py (pae_cutoff 10, dist 10), read from the two asym rows (A→B and B→A) and taking the minimum of the two directions per structure — the same definition the reference uses per predictor. It is a pure‑PAE quantity, so it is invariant to relaxation (verified Δ = 0.0000).
  • sc_DockQ — DockQ (v2.1.3) of the predicted pose against the designed backbone, i.e. how faithfully the co‑folder reproduces the intended docking geometry.

Evidence

Source labels used throughout: localColabFold = our AF2‑multimer recycle‑1 predictions and metrics; dataset = the reference Anthropic PD‑L1 design set and its published per‑model metrics. Comparisons are always local‑vs‑dataset, never framed as two competing authors.

01 · Generation

Backbones, sequences, and the pre‑scoring gate

Everything upstream of the complex screen — how 52 RFdiffusion backbones became the 1,050 folded, diverse candidates that the rest of the report starts from.

1 · RFdiffusion → 52 backbones

Binder backbones were generated with RFdiffusion against the PD‑1‑binding face of PD‑L1, seeded from three crystal complexes — 5C3T, 4ZQK, 4Z18 — plus a set of de novo pdl1_binder scaffolds, with hotspot residues fixed on the PD‑1 epitope (Y56 / R113 / M115 / Y123). 52 diverse backbones were carried forward.

2 · ProteinMPNN + SolubleMPNN → 4,905 sequences

Every backbone was sequence‑designed by both ProteinMPNN and SolubleMPNN at sampling temperature 0.2, giving 4,905 sequences (2,716 Soluble / 2,189 Protein). A per‑backbone cap trimmed these to a 2,481‑sequence candidate pool (6–97 sequences per backbone), each assigned a stable candNNNNN id. The pool is spread across the four scaffold families:

3 · ColabFold monomer foldability → 2,162

All 2,481 candidates were folded as monomers with localColabFold. The gate is deliberately loose — pLDDT ≥ 70, the dataset default — because monomer foldability is only a sanity check, not the ranking signal (binder quality is decided later at the complex stage). Median monomer pLDDT was 91.7; 93.5% cleared the pLDDT bar and 2,162 passed the full gate. SolubleMPNN folded slightly better than ProteinMPNN (median 93.0 vs 90.3) — expected, since it biases toward soluble, stable sequences.

4 · Redundancy & diversity down‑sample → 1,050

Finally the pool was de‑duplicated and diversity‑reduced by sequence identity. Exact‑redundancy dedup at 90% identity removed 0 sequences — 52 diverse backbones at MPNN temperature 0.2 simply produce no near‑duplicates. The real reducer is diversity down‑sampling at 70% identity, keeping the best‑folding representative per cluster, which collapsed the 2,162 survivors into the 1,050 complexes that entered the co‑fold screen.

Honest note on filter ordering
Ideally the millisecond‑cheap sequence filters (dedup, liability, novelty) run before any GPU folding. Here the monomer screen ran first and dedup/liability after — but because 90% dedup removed nothing, no folding compute was actually wasted (luck, not design). The 70% diversity step is deliberately kept after monomer folding, so the representative chosen per cluster is the best‑folding one (which needs the pLDDT/pTM scores) rather than a blind pick by MPNN score.

03 · Pipeline

End‑to‑end, backbones to a ranked top‑30

Each stage removes what the next, more expensive stage would waste effort on. Every count below is exact.

Generate (local, free)

RFdiffusion (52 backbones) → ProteinMPNN + SolubleMPNN (4,905 seqs) → monomer gate + 70% diversity → 1,050.

Triage & curate (local, free)

1,050 localColabFold co‑folds → ipSAE + sc_DockQ (242) → ΔΔG / CMS physics gate (157) → liability + clustering → 50.

Consensus (cloud, escalated)

Boltz‑2 + ESMFold2‑Full + Protenix must all agree on the pose → 43 → z‑rank → top‑30.

06 · Novelty

Are these just rediscoveries?

Sequence, yes — every one of the 43 survivors is a genuinely new sequence relative to the reference PD‑L1 design set. Fold, mostly not: superposed backbones land close to the nearest reference. Novelty here lives at the sequence level, not the fold level.

Each survivor’s sequence was aligned (global, BLOSUM62) against all 90 dataset PD‑L1 designs. The maximum identity to any reference design, over the entire top‑30, is 44.6%; the range across the top‑30 is 28.9–44.6%, most sit near 33–40%. Nothing approaches the ≥50% identity / ≥50% coverage band that the dataset methodology treats as a redundancy hit. In short: at the sequence level, the pipeline generates sequences distinct from the reference set for the same epitope, rather than memorising the reference binders.

Context from the dataset
The reference PD‑L1 set contains 90 designs, of which 39 are experimentally confirmed binders spanning Kd 0.6–2618 nM. For 13 of our top‑30, the nearest (still <45% identical) reference neighbour is one of those confirmed binders. The candidates occupy sequence‑space neighborhoods containing experimentally validated binders in the reference dataset, providing a useful contextual anchor for downstream testing.

Same epitope, new backbone — cand00725 vs its nearest reference

How similar is the backbone fold? (Cα / TM‑align)

Sequence identity alone does not say whether the underlying backbone fold is also new. Each top‑30 binder chain was isolated and TM‑aligned (Zhang Lab TM-align) against the binder chain of every reference PD‑L1 design that has a released “as‑designed” backbone structure — 78 of the 90 dataset rows (the other 12 ship only co‑fold prediction files, no ground‑truth backbone, so they cannot be TM‑aligned). Note this reference set is not some curated “top‑25”: earlier passes of this analysis had only 25 of the 90 structures cached locally (a leftover partial pull), which understated fold conservation; the numbers below are the full 78/90 sweep.

Result: the TM‑score to the nearest reference ranges 0.696–0.816 across the top‑30, median 0.788, and every one of the 30 clears the TM ≥ 0.5 “same fold” threshold used in the structure literature — none is below 0.70. Put plainly: the backbone fold is essentially always recovered, even where the sequence is <45% identical. That is not a failure of the pipeline — a rigid, well‑packed helical bundle is close to the only physically sensible shape for burying this epitope at this size, so independent generative runs (ours and the dataset’s) keep re‑deriving it. The distinguishing feature of these designs is a new sequence for a converged fold, rather than a new fold.

The closest single pair in the whole top‑30 × 78 sweep is cand01514 vs mythos_preview_single_target_pdl1_rank06 at TM = 0.815 (global max 0.816). Rank06 is itself an experimentally confirmed binder (Twist Kd 3.0 nM, Adaptyv Kd 29.5 nM, both assays agree it binds). The two chains are only 28.9% sequence‑identical. Aligning the two full complexes on their shared PD‑L1 target (109 Cα, RMSD 0.49 Å) shows the fold match is not a coincidence of isolated‑chain alignment: the two binders also occupy the same pose on the epitope.

07 · Limitations

What this pipeline does not do

The biggest gap versus the reference methodology is not a metric threshold — it is a missing loop.

No optimization loop
The Anthropic recipe this work reproduces is a single round of a process meant to run ≥5 rounds: predict, then redesign around what the prediction revealed, feeding the best‑scoring PD‑L1 complex from round N back in as structural input for round N + 1 (e.g. re‑diffusing or re‑designing around the observed interface, partial‑diffusion on a promising backbone, or MPNN resampling focused on weak contacts). This pipeline does generate → filter → rank exactly once. Every design in the top‑30 is a first‑generation candidate that was never revised in response to its own folding or interface metrics.

Why: each round of the full recipe costs another pass of RFdiffusion backbones, MPNN sequences, and co‑fold scoring — on one 8 GB consumer GPU plus rate‑limited free cloud co‑folders, a single round already took the bulk of the compute budget for this project (see “Why” above). Running five was not feasible in the time available.

What it means in practice: (1) these results are a floor, not a ceiling — a redesign loop would very plausibly improve the top hits further, not just re‑confirm them; (2) the novelty numbers above (28.9–44.6% identity, TM 0.70–0.82) describe first‑pass diversity only, before any loop had a chance to either converge candidates further toward known solutions or push them away from converged folds; (3) selection here is entirely in‑silico (ipSAE / sc_DockQ / ΔΔG‑CMS) — no wet‑lab affinity measurement closes the loop the way Adaptyv/Twist SPR does in the reference dataset. This is a single‑pass structural screen, not a closed‑loop design campaign.
